# v0.41.0 (2026-08-11)

## 🎯 核心变更

### Button 两字间距改为直接插入空格

原实现为「响应式镜像 + 双层节点 + letter-spacing 负 margin 补偿」，涉及四段协作逻辑：

- `slotText` ref 作为按钮文字的响应式镜像
- `onUpdated` + `nextTick` 每次 DOM 更新后回读 `textContent` 同步镜像
- `hasTwoCNChar` computed 依赖镜像求值，在 root 上挂 `hmfw-btn-two-chinese-chars`
- CSS 用 `letter-spacing: 0.34em` + `margin-right: -0.34em` 在内层 `hmfw-btn-two-chinese-chars-content` 上撑开字距并抵消尾部空隙

新实现在 render 函数内直接判定：slot 为单一纯文本 vnode 且去空格后是两个中文字符时，把文本拆开用空格连接（`按钮` → `按 钮`）。

**收益**：

- 移除 `onUpdated` / `nextTick` / `slotText` / `hasTwoCNChar` 四处状态，不再有「DOM 回读驱动 class」的反向数据流
- 不再需要每次更新后回读 `textContent`，也不再有镜像滞后一帧的时序窗口
- 删除 root 上的 `hmfw-btn-two-chinese-chars` 与内层 `hmfw-btn-two-chinese-chars-content` 包裹节点，两字按钮的 DOM 与普通按钮完全一致
- 删除对应 CSS 规则，字距不再依赖 `letter-spacing` 与负 `margin` 的相互抵消

**行为差异**：字距由真实空格字符产生，而非 `letter-spacing`，视觉宽度与 AntD 的 `0.34em` 方案存在细微差别。若此前有样式覆盖 `.hmfw-btn-two-chinese-chars-content`，该选择器已不复存在，需改为针对 `.hmfw-btn-content`。

### Modal 根节点类名修正为 `hmfw-modal-root`

修复 v0.40.0 记录的已知问题：`Modal.tsx` 的最外层容器与内层 dialog 节点都渲染成 `hmfw-modal`，同一 DOM 树中出现两个同名类名，造成三重后果：

- 4 条 Modal E2E 在 `.hmfw-modal` 上触发 Playwright strict mode violation
- 语义化 API 文档标注 `classNames.root` 作用于 `.hmfw-modal`，而 `classNames.content` 也指向 `.hmfw-modal`，两个节点无法区分
- 样式表中 `.hmfw-modal` 被声明两次且语义冲突（一次是 `position: fixed; inset: 0` 的全屏容器，一次是对话框外层盒）

现根节点渲染 `hmfw-modal-root`，CSS 与 `modal.md` 的 DOM 映射同步更新。`classNames.root` / `styles.root` 的挂载点语义不变，仅实际类名从 `hmfw-modal` 变为 `hmfw-modal-root`。
