# v0.30.0

发布日期：2026-08-02

本次为 ConfigProvider 专项审查与修复，含一处**行为变更**（嵌套配置继承）与一处**全站级缺陷修复**（嵌套主题串色）。

## 💥 行为变更

### 嵌套 ConfigProvider 现在继承父级配置

此前内层 ConfigProvider 从**库默认值**构建上下文，导致外层配置被静默重置：

```vue
<ConfigProvider component-size="large" :locale="enUS" direction="rtl">
  <ConfigProvider :theme="{ colorPrimary: 'orange' }">
    <!-- 修复前：size 退回 middle、locale 退回 zhCN、direction 退回 ltr -->
    <!-- 修复后：三者均继承外层，内层只覆盖 theme -->
  </ConfigProvider>
</ConfigProvider>
```

现在每个属性逐项回退到父级，`theme` 为**部分覆盖**语义（未列出的 seed token 继承外层，而非回落到库默认值）。与 AntD 及本仓 Form 的上下文处理方式一致。

**影响**：若此前依赖「内层重置为默认值」的行为，需在内层显式声明这些属性。

## 🐛 缺陷修复

### ConfigProvider

- **嵌套 theme 注入 `:root` 造成全站串色**：任意层级的 ConfigProvider 都把 CSS 变量写进 `document.documentElement`，后挂载者覆盖先挂载者。文档站的暗色模式 Demo 因此会把整个站点变暗

  修复后：根 Provider 仍注入 `:root` 且**不产生任何 DOM**；嵌套 Provider 渲染一个 `display: contents` 的作用域节点承载局部变量，该节点不产生盒模型、不进无障碍树，对布局与语义透明。作用域节点只输出**与父级不同**的 token

- **`getPopupContainer` 无人消费**：该属性被声明、被 provide，但所有弹层组件都未读取，配置了等于没配。现 Trigger 按「组件自身 prop → ConfigProvider 配置 → `document.body`」优先级回退，Tooltip / Popover / Dropdown / Select 等均受益

  同时默认值由 `() => document.body` 改为 `undefined`，以区分「未配置」与「显式配置为 body」，并避免模块求值期访问 `document`（SSR 安全）

- **嵌套 Provider 未输出 `dir`**：`direction` 只走 context，DOM 上无 `dir` 属性，浏览器原生双向文本算法与 `:dir()` 选择器均无法生效。现作用域节点在指定 `direction` 时写出 `dir`

- **`theme.prefix` 为死字段**：类型中声明但无任何读取处，已移除

## 📖 文档与 Demo

- **Demo 5 → 7**，并修正两处误导：
  - 新增「嵌套与局部主题」：演示配置继承与主题作用域隔离
  - 新增「全局禁用」：演示 `componentDisabled`，并明确「容器禁用时控件无法单独反禁用」
  - 新增「布局方向」：演示 `direction`，标注当前支持 RTL 的组件范围
  - 移除「紧凑间距」：该 Demo 实为手动给各控件传 `size`，与 ConfigProvider 无关
  - 重写「国际化」：原 Demo 只打印 `locale.locale` 字符串，看不出语言包作用。现改用真实消费语言包的组件（Select 占位符、Empty 空状态、Popconfirm 按钮文案）
- **API 表补 `getPopupContainer`** 条目（此前缺失），并说明所有属性支持嵌套继承
- **SeedTokens 表由 16 项补齐为 23 项**，补上 `lineHeightBase`、`motionDurationFast/Mid/Slow`、`motionEaseInOut`、`motionEaseOut`、`boxShadowPopoverArrow`；MapTokens 数量由「~110」修正为准确的 115
- 新增「嵌套行为说明」与「Hooks」章节，说明 `useConfig` / `usePrefixCls` / `useLocale` / `useMergedDisabled` 的用途
- 明确 **`prefixCls` 不支持运行时切换**：类名在挂载时求值，运行时修改只会更新 CSS 变量名而不更新类名，二者会脱节

## 📊 质量提升

- ConfigProvider props 补 `satisfies Record<keyof ConfigProviderProps, unknown>` 约束，并复用共享 `ComponentSize` 类型，消除与 `types.ts` 的双源头漂移
- `theme.ts` 抽出 `tokensToCssVarRecord`，供 `injectCssVars` 与作用域节点共用，避免 kebab-case 转换逻辑重复（纯重构，生成的静态 CSS 无 diff）
- **ConfigProvider 单测 12 → 30**：原「injects CSS variables on mount」是伪断言（取了变量却只断言 `wrapper.exists()`）。新增覆盖嵌套继承、主题作用域隔离与 token 精简输出、`useMergedDisabled` 四种组合、`getPopupContainer` 经 Tooltip 的真实回退、`:root` 实际注入、`dir` 写入条件
- 单测总数 2382 → 2400，全部通过

## ⚠️ 已知限制

- **`componentSize` 覆盖面仅 6/26**：声明了 `size` prop 的 26 个组件中，只有 Input 系列、AutoComplete、Rate、Segmented、Skeleton、Form 会回退到全局配置。Button、Select 等因 `size` 硬编码 `default: 'middle'`，无法区分「未传」与「显式传 middle」，永远轮不到全局值 —— 与本次修复的嵌套问题同源。补齐需改动 20 个组件的 props 默认值并逐个回归，另行立项。当前生效范围已在 Demo 与文档中标注

- **`direction` 覆盖面有限**：仅 Rate、Progress、Statistic、Descriptions、Segmented、Skeleton 响应，其余组件不加 `-rtl` 类。已在 Demo 中标注

- **`locale` 不支持部分覆盖**：`Locale` 所有字段必填，只想改一两条文案也必须提供完整语言包。需引入 `DeepPartial` 与深合并，属功能增强
