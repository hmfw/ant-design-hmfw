# v0.42.0 (2026-08-12)

## 🎯 核心变更

### Button 语义化 API 移除 `loading` 键

`ButtonClassNames.loading` 与 `ButtonStyles.loading` 已删除，Button 的语义节点收敛为 `root` / `icon` / `content` 三个，与 Ant Design v6 的 `ButtonSemanticType` 完全一致。

**移除原因**：

- `loading` 从来不是独立 DOM 节点。实现上它被叠加到 `icon` 那个 `<span>` 上（class 与 `classNames.icon` 并列，style 合并且优先级更高），本质是「节点的状态修饰键」，不是语义节点，与 `classNames` / `styles` 描述结构的定位不符
- 命名与同名 prop `loading` 撞车。`classNames` 里的 `{ loading: 'x' }` 与 props 上的 `loading` 含义完全不同，容易误读
- 能力本身冗余。加载图标容器上已有稳定内置类 `.hmfw-btn-loading-icon`，root 上有 `.hmfw-btn-loading`，纯 CSS 定制加载态的路径不受影响
- Ant Design v6 处理状态相关样式走的是 `classNames` 的函数形式（`classNames={({ props }) => ({ icon: props.loading ? 'x' : '' })}`），并未新增语义键。本项目暂无函数形式，此前用一个额外键顶替，现回归结构语义

**实现简化**：`renderIcon` 中的 class 叠加与 style 合并逻辑一并删除，`style` 直接取 `props.styles?.icon`。内置类 `.hmfw-btn-loading-icon` 与 root 上的 `.hmfw-btn-loading` 保持不变。

### 删除 `.hmfw-btn-icon-end` 空规则块

样式表中 `.hmfw-btn-icon-end { }` 是一个没有任何声明的空块，对渲染零影响。类名本身仍由组件输出，`.hmfw-btn-icon-end .hmfw-btn-icon { order: 1 }` 继续用它作选择器。原先分散在两处的注释合并到实际生效的规则上。

---

**Breaking Changes**:

- `ButtonClassNames.loading` / `ButtonStyles.loading` 已移除。原先写 `:class-names="{ loading: 'x' }"` 的调用方会**静默失效**（Vue 不会对对象中多余的 key 报警）。迁移方式二选一：
  - 改用 `icon` 键 —— 加载图标复用 `icon` 容器，`classNames.icon` / `styles.icon` 在加载态同样生效；
  - 只想影响加载态时，用内置类选择器 `.hmfw-btn-loading-icon`（图标容器）或 `.hmfw-btn-loading`（根节点）编写 CSS
