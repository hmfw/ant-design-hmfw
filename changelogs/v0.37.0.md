# v0.37.0 (2026-08-04)

## 💥 破坏性变更

### Trigger 内部原语架构重构

移除 `cloneChild` 和 `triggerDisplay` 两个复杂 API，大幅简化内部实现，提升可维护性和稳定性。

**移除的 API**：

- ❌ `cloneChild` prop：不再支持克隆子节点模式（SubMenu / MenuItem 已改用自建根元素适配）
- ❌ `triggerDisplay` prop：不再管理 wrapper 的 display 样式（宿主组件改为自建根元素）

**保留的 API（向后兼容）**：

- ✅ `triggerClass` / `triggerStyle`：继续支持，内部映射到 wrapper

**新增约束**：

- Trigger 子节点必须是**单个元素或组件 vnode**
- 拒绝文本节点、注释节点、多个子节点（会输出警告并跳过渲染）
- Tooltip / Dropdown 在宿主侧对文本节点包 `<span>` 兜底

## 🐛 Bug 修复

- **SubMenu**: 修复 click 模式下 onClick 双触发问题（Trigger 的 click 和手动调用 `onOpenChange` 重复）

## ♻️ 代码重构

### 宿主组件适配（8 个）

**自建根元素**（5 个）：

- **Select** / **TreeSelect** / **TimePicker** / **RangePicker** / **ColorPicker**：在 Trigger 的 default 插槽内自建根 div，承载原本通过 `triggerClass` / `triggerStyle` 传递的根类和样式

**宿主侧兜底**（2 个）：

- **Tooltip** / **Dropdown**：对文本节点、注释节点包一层 `<span>` 兜底，确保 Trigger 始终收到合法 vnode

**其他调整**：

- **FloatButtonGroup**：移除 `triggerDisplay="block"` 传递（已自建根元素）
- **MenuItem**：移除 `cloneChild` 相关代码和注释

### CSS 清理

- 移除 Trigger 的 `:where(.hmfw-trigger)` 默认 display 规则（宿主组件自行管理）
- 移除 Dropdown 的 `.hmfw-dropdown-trigger` 无用类

### 测试改写

- 删除 Trigger 的 `cloneChild` describe 块（197 行，11 个测试用例）
- 删除 4 个 `triggerDisplay` 相关测试
- 批量替换 `wrapper.find('div')` → `wrapper.find('button')`（约 100 处）
- 修复 Dropdown / FloatButton 测试中的定位 stub 和事件触发逻辑
- 新增 Menu SubMenu onClick 双触发验证（E2E）

## 📝 迁移指南

### 影响范围

**直接使用 Trigger 的场景**（极少）：

- 如果代码中显式传递了 `cloneChild` 或 `triggerDisplay`，需要改为自建根元素
- 如果传递文本节点作为子节点，需要包一层 `<span>` 或其他元素

**使用高层组件的场景**（大部分）：

- Select / Dropdown / Tooltip / Popover / DatePicker 等组件的 API **完全不变**
- 无需修改任何调用代码

### 迁移示例

**移除前**（SubMenu 使用 cloneChild）：

```tsx
<Trigger cloneChild triggerDisplay="contents">
  <li class="menu-item">SubMenu</li>
</Trigger>
```

**移除后**（自建根元素）：

```tsx
<Trigger>
  <div class="submenu-root">
    <li class="menu-item">SubMenu</li>
  </div>
</Trigger>
```

## 🎯 收益

1. **降低复杂度**：Trigger 代码减少 30%，核心逻辑更清晰
2. **提升稳定性**：移除 clone 相关的边界情况和告警分支
3. **简化维护**：宿主组件自建根元素，样式控制权归属清晰
4. **保持兼容**：高层组件 API 完全不变，用户代码无感知
