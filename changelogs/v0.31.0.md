# v0.31.0 (2026-08-02)

App 组件全面审查与修复。

## 🐛 缺陷修复

### App

- **修复 modal 方法功能严重缺陷**
  - 原实现自己维护状态，导致功能残缺：不支持 `content`、`icon`、`onOk`、`onCancel` 等属性，返回 `void` 而非 `{ destroy, update }`，多次调用相互覆盖
  - 现直接调用 `Modal.confirm/info/success/warning/error` 静态方法，功能完整，代码简化 50%（60 行 → 30 行）

- **修正 modal 方法类型签名**
  - `types.ts`: 参数改为 `ModalFuncProps`，返回值改为 `ModalFuncReturn`
  - `context.ts`: `defaultModal` 返回正确的 `{ destroy, update }` 结构
  - TypeScript 提示现在完整准确

## ✨ 新增功能

### App

- **实现 message/notification 配置传递**
  - 创建 `createMessage(config?)` 和 `createNotification(config?)` 工厂函数
  - 支持 `<App message={{ maxCount: 2, duration: 5 }} notification={{ placement: 'topLeft' }}>` 配置传递
  - 每个 App 实例拥有独立的 message/notification 实例
  - 完全向后兼容：全局单例 `message.success()` / `notification.info()` 仍可用

- **新增 AppProps 接口**
  - `message?: MessageConfig` - App 内 Message 的全局配置
  - `notification?: NotificationConfig` - App 内 Notification 的全局配置
  - `component?: string | false` - 设置渲染元素，`false` 则不创建 DOM 节点
  - `style?: CSSProperties` - 容器内联样式
  - `className?: string` - 容器 class
  - `rootClassName?: string` - 根容器 class

### Message

- **新增 `createMessage(config?)` 工厂函数**
  - 支持创建独立实例，每个实例拥有独立配置和状态
  - 导出 `export { createMessage }` 供 App 组件使用

### Notification

- **新增 `createNotification(config?)` 工厂函数**
  - 支持创建独立实例，每个实例拥有独立配置和状态
  - 导出 `export { createNotification }` 供 App 组件使用
  - 新增 `NotificationApi` 类型别名（等同于 `NotificationInstance`）

## 🔧 技术细节

### 工厂函数模式

**修复前**（全局单例）:

```typescript
let globalConfig = { duration: 3, top: 8 }
export const message = { open, config, ... }
```

**修复后**（工厂函数 + 全局单例）:

```typescript
// 工厂函数，支持独立实例
export function createMessage(config?: ConfigOptions): MessageApi {
  let instanceConfig = { duration: 3, top: 8, ...config }
  // 每次调用创建独立实例，拥有独立状态
  return { open, config, success, error, ... }
}

// 全局单例（向后兼容）
export const message = createMessage()

// App 中使用（独立实例）
const appConfig = {
  message: createMessage(props.message),
  notification: createNotification(props.notification),
}
```
