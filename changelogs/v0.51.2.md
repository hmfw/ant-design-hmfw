# v0.51.2 (2026-10-02)

## 🐛 问题修复

### 组件插槽写法全库规范化（修复消费方「Non-function slot」告警与 `v-slots` 失效）

修复 `RadioGroup`（`options` 驱动渲染）等组件向「子组件」传入裸子节点（字符串 / VNode / 数组 / 三元 / `&&`）时，在**已发布产物**中触发 Vue 3.5 告警「Non-function value encountered for default slot」的问题。

根因是两条 JSX 工具链语义不一致：开发 / 文档 / 单测走 Babel（`@vue/babel-plugin-jsx`）会自动把组件子节点包成函数插槽，而库产物此前走 esbuild automatic runtime 不做包裹——因此该类告警只在消费已发布包的用户侧出现，仓库内 dev 与单测永远复现不了。此外 `v-slots={{...}}` 是 Babel 专有写法，在 esbuild 产物里会被当普通 prop 透传，导致**插槽内容完全不渲染**（比告警更严重）。

本次一次性清理：

- 22 处「组件裸子节点」统一改为函数插槽 `{() => ...}` 或插槽对象 `{{ default: () => ... }}`，涉及 Radio、Anchor、Breadcrumb、DropdownButton、MenuItem、Progress、Segmented、List、ListItem、Calendar、Splitter、ConfirmDialog、Modal、Transfer、TransferList、Rate、FilterDropdown、CheckableTagGroup、Typography（Base/Link/Paragraph/Text/Title）、FloatButton、AvatarGroup 等
- 4 处 `v-slots`（CheckboxGroup、Masonry、Table、AvatarGroup）改为 children 插槽对象写法

均为写法规范修复，无运行时行为变更。

## 🔧 构建 / 工程

### 库构建改用 `@vue/babel-plugin-jsx`，与开发态语义彻底对齐（根治插槽类 bug）

tsup 构建此前用 esbuild 的 automatic runtime（`jsx:'automatic'` + `jsxImportSource:'vue'`）转换 `.tsx`，不包裹组件插槽、不认 `v-slots`，与开发 / 文档 / 单测所用的 Babel（`@vitejs/plugin-vue-jsx`）语义不一致，是上述插槽类 bug 反复逃过自测的根本原因。

本次在 tsup 的 esbuild `onLoad` 阶段拦截 `.tsx`，改用与 `@vitejs/plugin-vue-jsx` **完全相同**的 Babel 插件链（`@vue/babel-plugin-jsx` + `@babel/plugin-transform-typescript`，版本对齐），使 **dist 与 dev 走同一套 JSX 转换**：组件子节点自动包成函数插槽、`v-slots` 正常工作，该类 bug 从构建层被结构性消除。`bundle:false` 的逐文件产物、tree-shaking、UMD 构建均不受影响；并为 `defineComponent` 调用补上 `/* @__PURE__ */` 标注，利于下游 tree-shaking。

验证：`build:lib` / `typecheck` / 2605 单测全部通过；产物已全部改用 `createVNode`，无残留 `jsx()` / `vue/jsx-runtime` / `v-slots`。
